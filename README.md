# AiWebCity

Бесплатный городской проект для Новороссийска. Пользователь загружает фотографию
здания, а сервис определяет, что это за объект, доказывает совпадение по реальным
фотографиям и ищет исторические снимки этого места.

Полный контекст проекта и история решений — в [PROJECT_HISTORY.md](PROJECT_HISTORY.md).

## Пайплайн идентификации

```
ФОТО ПОЛЬЗОВАТЕЛЯ
    ↓
Yandex CBIR (один запрос отдаёт сразу пять сигналов):
    cbirSites    — сайты с точно этим же файлом
    cbirSimilar  — до 40 визуально похожих изображений
    cbirTags     — текстовые догадки Яндекса («губернского 1 новороссийск»)
    cbirPreview  — bbox объектов от детектора («здание», «машина», «растение»)
    cbirOcr      — текст, распознанный на самой фотографии
    ↓
КРОП ЗДАНИЯ по bbox детектора → повторный поиск (ещё 1–2 запроса)
    ↓
ПУЛ КАНДИДАТОВ (обычно 50–100) → дедупликация по yandex image id
    ↓
ТЕКСТОВЫЙ РАНКИНГ под Новороссийск (только порядок проверки, не доказательство)
    ↓
ЗАГРУЗКА ОРИГИНАЛОВ на нашей стороне + нормализация в JPEG
    ↓
ВИЗУАЛЬНАЯ ВЕРИФИКАЦИЯ top-N через Timeweb Vision, параллельно
    ↓
ПЕРЕПРОВЕРКА АДРЕСА: подписи подтверждённых кандидатов + cbirTags + OCR
                     → OpenStreetMap / Nominatim, только Новороссийск
    ↓
ИСТОРИЧЕСКИЕ ФОТО: PastVu по координатам + Wikimedia Commons
```

Генерация исторических изображений намеренно выключена (`generation: false`).
Сначала сервис должен научиться доказывать, что за здание на фото.

## Ключевой принцип

Адрес — не доказательство, а перепроверка.

Сначала визуальное совпадение по архитектурным признакам, и только потом адрес.
Подсказка пользователя имеет минимальный вес: она не должна подтверждать сама себя.
Если доказательств мало, сервис отвечает «не подтверждено», а не выдаёт догадку.

## Статусы ответа

| status | что значит |
|---|---|
| `identified` | здание подтверждено визуально И адрес перепроверен по OSM |
| `visual_only` | здание подтверждено визуально, адрес подтвердить не удалось |
| `uncertain` | надёжного визуального совпадения нет |
| `verification_unavailable` | Vision недоступен (лимит/сбой) — это не то же самое, что «не найдено» |

## Обратный поиск

Поиск по Яндексу работает через собственный клиент `app/yandex_cbir.py`.

Так сделано намеренно: PicImageSearch читает из ответа Яндекса только
`initialState.cbirSites.sites` — блок «сайты, где встречается ЭТА ЖЕ картинка».
Для обычного кадра с телефона он почти пуст, поэтому весь сервис получал
единицы кандидатов и не мог найти другие фотографии того же здания. Собственный
парсер берёт из того же самого HTTP-ответа ещё и похожие изображения, подсказки,
кропы объектов и OCR.

PicImageSearch остаётся зависимостью только ради Google Lens и импортируется лениво.

Это не официальный Yandex Cloud API: внешний поисковик может ввести капчу,
rate limit или поменять разметку. Поэтому движок считается ненадёжным адаптером,
ошибки не роняют запрос, капча распознаётся отдельно, а ответы кэшируются.

## Запуск

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # и заполнить TIMEWEB_AI_TOKEN
uvicorn app.main_pic:app --host 0.0.0.0 --port 8000
```

Проверка:

```bash
curl http://127.0.0.1:8000/api/health
```

## Приватность

Фотография пользователя не записывается на VPS: она живёт в памяти процесса на
время обработки. При обратном поиске фото передаётся внешним сервисам (Яндекс,
Timeweb AI) — это указано в интерфейсе.

## Ограничения окружения

VPS имеет 889 МБ RAM. Пиковое потребление процесса под нагрузкой — около 130 МБ.
Не поднимайте `VISION_CONCURRENCY` выше 3 и не убирайте ограничения на размер
скачиваемых изображений: без них процесс уходит в OOM.
