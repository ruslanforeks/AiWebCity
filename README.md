# AiWebCity

Бесплатный городской проект для Новороссийска. На первом этапе пользователь загружает фотографию здания и адрес, а сервис пытается понять, что это за объект, ищет визуальные совпадения и исторические фотографии.

## Текущий MVP

`Фото здания + адрес + необязательный год`

→ анализ фасада через Timeweb AI Vision

→ формирование кандидатов на идентичность и поисковых запросов

→ геокодирование адреса

→ reverse-image поиск через PicImageSearch

→ Yandex Images и Google Lens как внешние поисковые движки

→ поиск исторических фотографий рядом с координатами через PastVu API

→ поиск изображений в Wikimedia Commons

→ дополнительная ссылка на PastPhoto

→ объединение и вывод найденных источников пользователю

Генерация исторических изображений на этом этапе полностью отключена. Сначала сервис должен научиться находить реальные источники и сопоставлять объект.

## Reverse image search

Для reverse-image поиска используется бесплатная open-source библиотека PicImageSearch. Она выступает как адаптер к внешним поисковым движкам и умеет отправлять фотографию непосредственно на Yandex Images и Google Lens.

Это **не официальный Yandex Cloud API**. Поэтому у такого подхода нет платы за каждый запрос к Yandex Cloud API, но внешние поисковики могут применять собственные ограничения, CAPTCHA, rate limits или менять интерфейс. Поэтому код должен рассматривать reverse-image движки как независимые адаптеры, а не как гарантированный постоянный API.

Пример установки:

```bash
pip install PicImageSearch
```

Для текущего приложения reverse search включён параметром:

```env
REVERSE_SEARCH_ENABLED=true
REVERSE_SEARCH_TIMEOUT=45
REVERSE_SEARCH_RESULTS=20
```

Если reverse search временно заблокирован внешним поисковиком, приложение продолжает использовать другие источники: PastVu, Wikimedia Commons и текстовый анализ.

## Открытые источники

### PastVu

Официальный API PastVu используется для поиска исторических фотографий вокруг найденных координат с ограничением по году.

### Wikimedia Commons

MediaWiki API используется для поиска фотографий по названиям, адресам и поисковым запросам, которые формирует модуль идентификации.

### PastPhoto

PastPhoto используется как дополнительный исторический источник. В текущем MVP пользователь получает ссылку на страницу соответствующего места для ручной проверки. Критическая логика не зависит от хрупкого HTML-скрейпинга.

### OpenStreetMap / Nominatim

Адрес преобразуется в координаты для пространственного поиска. При высокой нагрузке публичный Nominatim нужно будет заменить на отдельную геокодирующую инфраструктуру.

## Yandex Maps

Платные Organization/Places API Яндекс.Карт в бесплатное ядро не входят. На следующих этапах они могут быть полезны для более точного сопоставления адреса с современным объектом или организацией.

## Приватность

AiWebCity не сохраняет загруженную фотографию пользователя на VPS. На сервере фото находится только в памяти процесса на время запроса.

Важно: для reverse-image поиска фотография временно передаётся внешним сервисам Yandex Images и Google Lens через PicImageSearch. Полная приватность от этих сторонних сервисов не может быть гарантирована самим AiWebCity; действуют их собственные правила обработки данных.

## Переменные окружения

```env
TIMEWEB_AI_TOKEN=ваш_ключ
TIMEWEB_API_BASE=https://api.timeweb.ai/v1
TIMEWEB_VISION_MODEL=openai/gpt-4.1-mini

REVERSE_SEARCH_ENABLED=true
REVERSE_SEARCH_TIMEOUT=45
REVERSE_SEARCH_RESULTS=20

MAX_UPLOAD_MB=12
```

## Запуск

```bash
git clone https://github.com/ruslanforeks/AiWebCity.git
cd AiWebCity
cp .env.example .env
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main_pic:app --host 0.0.0.0 --port 8000
```

Откройте `http://SERVER_IP:8000`.

## Принцип достоверности

Vision-модель должна отделять видимые признаки от предположений и не выдавать исторические сведения без источника. Сам факт того, что поисковик нашёл похожую фотографию, не считается доказательством идентичности здания.

Финальная идентификация должна опираться на совокупность признаков: адрес, география, архитектурный отпечаток, совпадающие детали фасада, контекст и независимые источники.

## Следующий этап

После проверки reverse-image поиска можно улучшить reranking: передавать лучшие найденные изображения в Vision-модель и отдельно сравнивать фасады. Только после проверки идентификации возвращаемся к исторической реконструкции.
